# 모두의 폰트 스킬 (modu-font) — 참고 이미지 한 장의 글씨체로 폰트 만들기

원하는 글씨체의 참고 이미지(손글씨 사진이나 AI 시안)를 견본으로, 이미지 생성 모델이 격자에 한 칸 한 글자씩 쓰게 하고, 칸을 잘라 사람이 확인한 뒤 윤곽을 따서 TTF(보통·굵게)로 조립한다. 한국어 본문은 견본의 획 굵기를 재서 14×14 나 12×12 격자로 쓰고(첫 장이 장 검사에 떨어지면 같은 격자로 한 번 더 받고, 또 떨어지면 6×6 까지 한 단계씩 낮춘다), 일본어와 영문 장은 6×6 이다. 모드: 한국어(기본, `references/korean.md`) · 일본어(`references/japanese.md`) · 영문 더하기(`references/latin.md`). 처음 만든 결과물: "모두의 둥글펜"(한글 2,338/2,350자 + 영문, 일본어판 포함 — 6×6 으로 만들었다).

모든 명령: `node scripts/hf.mjs <명령> <작업 폴더> [옵션]` (목록 `references/commands.md`). 작업 폴더는 사용자 프로젝트 안 아무 곳(예: `./my-font`).

## 0. 시작 전에 사용자와 정할 것 (짧게 묻는다)
1. **견본**: 손글씨 사진이 있나, 아니면 AI 시안 4개(`drafts`)에서 고를까?
2. **글자 수**: 말풍선용 약 500자(`--count 500`) / KS X 1001 전체 2,350자. 장 수는 격자에 따라 다르다(아래 표 — 부호·채팅 자모·숫자 36자 1장 포함, 다시 쓰기 장은 따로).
3. **그리는 방법(백엔드)** — 아래 표에서 하나. 섞어 써도 된다(받은 장은 모두 `inbox/` 로 모인다).
4. **이름**: 영어(`--family-en`)와 한국어(`--family-ko`). 남의 폰트·브랜드 이름(예: "나눔")은 쓰지 않는다.
5. **영문**: 같은 손글씨로 영문(대소문자·ASCII 부호, 3장 약 $1.3)도 넣을까? 넣으면 `init … --latin`(이미 만든 폴더는 `latin <dir>`). 자세히 `references/latin.md`.

**격자는 묻지 않는다 — 스킬이 견본을 재서 정하고 까닭을 한 줄로 말한다**(한국어 모드). 사용자가 정하고 싶어 하면 `init … --grid 6|8|10|12|14`.

| 격자 | 500자 | 2,350자 | 언제 |
|---|---|---|---|
| 14×14 | 4장 | 13장 | 가는 글씨(견본의 획 굵기 ÷ 글자 높이 < 0.09) |
| 12×12 | 5장 | 18장 | 굵은 글씨(0.09 이상) · 견본을 못 잰 때 |
| 10×10 | 6장 | 25장 | 낮춘 격자 |
| 8×8 | 9장 | 38장 | 낮춘 격자 |
| 6×6 | 15장 | 67장 | 마지막 격자 · 견본이 아직 없는 폴더(재면 바뀐다) · 격자 정보가 없는 옛 작업 폴더 · 일본어 · 영문 장 |

굵기는 둘로만 나눈다. **아주 굵은 글씨**(실험의 굵은 마커 — 획 ÷ 높이 0.17)는 12×12 첫 장에서 떨어지고 10×10 에서 됐다 — 그런 글씨는 12×12 에서 두 번 떨어진 뒤 10×10 으로 내려갈 수 있고, 그때 그림 두 장 값이 더 든다. 굵은 글씨의 견적을 말할 때 이것도 같이 말한다.

| 백엔드 | 돈 | 무엇을 하나 | 자세히 |
|---|---|---|---|
| B OpenAI 키 | 유료 | `hf.mjs openai` 가 이미지 편집 API 로 장마다 그려 `inbox/` 에 저장 | `references/backend-openai.md` |
| C 에이전트 도구 | 도구에 따라 | 지금 에이전트에 이미지 생성 도구(Codex 내장 image_gen, 이미지 MCP 서버 등)가 있으면 에이전트가 같은 묶음으로 직접 그려 `inbox/` 에 저장 | `references/backend-agent.md` |

기본값은 없다 — 사용자가 B 나 C 를 고른다. 에이전트에 이미지 도구가 있어도 **사용자가 C 를 고르기 전에는 쓰지 않는다.** (사람이 장마다 채팅 앱에 올려 받는 길은 0.5.0 에서 뺐다 — 수십 장을 손으로 주고받기엔 너무 길고 틀리기 쉽다.)

## 1. 흐름
```
init(견본 → 격자) → (drafts → pick) → jobs → estimate → approve → [B/C 로 첫 장] → cut(장 검사)
   ├ 첫 장 통과 → 사용자와 글씨 확인 → jobs → 나머지 장(받을 때마다 cut) → 검수(errors.json) → redo → jobs → … → glyphs → build → bold → build --bold → 설치
   └ 통과 못 함 → retry s01 → jobs s01 → 같은 격자로 한 번 더 → 또 통과 못 함 → grid --down → 새 견적 · 다시 승인 → jobs s01 → …
```
**첫 장 통과** = 첫 본문 장(s01)의 장 검사가 "됨"이고 빈 칸이 0 이고 그림이 정사각 · 긴 변 1,500px 이상인 것(빈 칸이 있는 6×6 첫 장은 "됨"이어도 통과가 아니다). 그때 그 그림이 형식 참조(`style/format.png`)가 된다. **첫 장이 통과하기 전에는 다른 한국어 장(본문 · 부호 · 다시 쓰기)으로 돈이 나가지 않는다** — `jobs` 가 묶지 않고, `spend` 가 적지 않고, `openai` 가 보내지 않는다(영문 장과 시안은 따로다).

1. `init <dir> --sample 견본.png --family-en "My Hand" --family-ko "내 손글씨" --style "<글씨 설명(영어)>" --count 500`
   - 견본이 없으면 `init <dir>` → `drafts <dir>` → 그림을 `inbox/drafts.png` 로 받기 → `pick <dir> --quad 1~4`.
   - `--style` 은 견본 글씨를 영어로 한 줄(예: "round, bubbly everyday handwriting with a thin black 0.5 mm gel pen (soft curves, big round ㅇ, chubby short letters)"). 프롬프트에 그대로 들어간다.
   - **격자는 견본이 정해질 때 잰다**: `init --sample` 때, 견본 없이 만들었으면 `pick` 때, 견본을 손으로 `style/sample.png` 에 넣었으면 다음 `jobs` 때(첫 장을 받기 전에는 `grid <dir> --auto` 로 다시 잴 수 있다). 견본에서 획 굵기와 글자 높이를 재서 `획 ÷ 높이 < 0.09 → 14×14(가는 글씨)`, `그 이상 → 12×12(굵은 글씨)`. 견본이 기울어 있으면(±12° 안) 글줄이 수평이 되게 되돌려서 잰다(`style/sample.png` 는 그대로 둔다). 화면에 `격자 14×14 — 견본의 획 굵기 ÷ 글자 높이 0.0602(획 8.3px ÷ 높이 138px) < 0.09 → 가는 글씨 → 14×14` 처럼 나오고 `font.json` 의 `grid` 에 남는다 — **이 한 줄과 장 수를 사용자에게 말한다.** 견본을 재지 못하면(글자 줄을 못 찾음 등) 12×12 로 두고 그렇게 알린다(굵은 글씨면 첫 장 검사가 10×10 으로 낮춘다 — 정하려면 `init --grid <N>` · `grid <dir> --set <N>`). 언제든 `grid <dir>` 로 지금 격자·근거·내려갈 차례를 본다.
2. `jobs <dir>` — 안 받은 장마다 묶음(`ref-1.png` 견본, `ref-2.png` 형식, `prompt.txt`, `job.json`). **첫 장이 통과하기 전에는 첫 한글 장(s01) 하나만 묶는다.** `--all` 은 묶음만 미리 만드는 것이다 — 그래도 첫 장 통과 전에는 첫 장만 그린다. 첫 장을 받았는데 통과하지 못한 채로 부르면 `jobs` 는 다른 한국어 장을 묶지 않고 멈추며 먼저 할 일을 말한다.
3. **견적 → 승인** — `estimate <dir>` 의 장 수 × 장당 값을 사용자에게 말하고 "예"를 받아 `approve`. 아래 "돈 규칙".
4. 그리기 — 백엔드별 문서대로. 첫 장(s01) 한 장만 먼저.
5. `cut <dir> <장>` — **받은 장은 장마다 바로 자른다**(떨어진 장을 일찍 안다). 한국어 장은 **장 검사**를 하고 찾은 선대로 자른다. 보는 것: (1) 하늘색 선이 가로·세로 N+1개인가 (2) 줄(행)마다 세로 선이 전체 선 자리에서 칸 너비의 15% 넘게 어긋나지 않았나(열마다 가로 선도 — 어긋난 선의 위·아래 행으로 센다) (3) 칸마다 글자가 하나인가(빈 칸 · 한 칸에 두 글자 · 글자가 선을 넘음). **6×6 은 빈 칸을 그 칸만 뺀다**(줄 판정에 넣지 않고 그 글자는 `redo` 로) — 8×8 이상은 빈 칸이 든 줄을 못 쓴다. "못 쓰는 줄"은 행(가로 줄)이고, 판정은 못 쓰는 줄 수 ÷ 행 수 N 으로 한다: 0 = **됨** · 20% 이하 = **일부**(그 줄의 칸만 폰트에서 빠진다) · 선 수가 틀리거나 20% 초과 = **안 됨**(그 장의 칸은 쓰지 않는다. 선 수가 틀리면 칸을 만들지 않는다). 선이 N+1개면 간격이 고르지 않아도 선대로 자른다. 격자마다의 숫자는 `references/korean.md`.

   `cut` 은 **다음 할 일을 `→ 다음:` 한 줄로 말하고**(같은 내용이 `cells/<장>/cells.json` 의 `next` 에), 화면의 첫 낱말과 종료 코드를 그 다음 할 일에 맞춘다:

   | 판정 | 화면 첫 낱말 · 종료 코드 | `next.action` |
   |---|---|---|
   | 됨 | `ok` · 0 | `go` 간다 |
   | 일부(첫 장이 통과한 뒤의 장) | `일부:` · 0 | `redo` 그대로 가고 못 쓰는 줄만 다시 쓰기로 |
   | 일부(첫 장) · 안 됨 · 정사각 아님 · 긴 변 1,500px 미만 | `경고:` · 2 | `retry` 같은 격자로 다시 · `down` 격자를 낮춘다 · `ask` 멈추고 묻는다 · `stop` 더 내려갈 격자가 없다 |

   **종료 코드 2(`경고:`)면 그 장은 통과가 아니다 — 다음 장으로 가지 않고 `→ 다음:` 을 따른다.** 아래에서 "두 번"은 그 격자에서 장 검사에 떨어진 그림의 수다(사용자가 통과한 그림을 치운 것은 세지 않는다).

   | 어느 장 | 무슨 일 | 다음 할 일 |
   |---|---|---|
   | 첫 본문 장 | 됨 | 첫 장 통과 — 이 그림이 형식 참조가 된다. 글씨가 견본과 같은지 사용자와 본 뒤 `jobs <dir>` 로 나머지 장. **이제 격자는 못 바꾼다**(한 폰트 한 격자) |
   | | 됨인데 사용자가 글씨가 견본과 다르다고 한다 | `retry <dir> s01`(형식 참조도 같이 치워진다) → `jobs <dir> s01` → 같은 격자로 다시. 격자는 낮추지 않는다. 두 번 받아도 다르면 멈추고 견본 · 글씨 설명(`--style`)을 사용자와 다시 본다 |
   | | 됨이 아님(일부도) — 그 격자에서 처음 | 같은 격자로 한 번 더: `retry <dir> s01` → `jobs <dir> s01` → 그리기 → `cut <dir> s01` |
   | | 됨이 아님 — 그 격자에서 두 번째 | 격자를 한 단계 낮춘다(14 → 12 → 10 → 8 → 6): `grid <dir> --down` → **새 견적을 말하고 다시 승인**(`approve --note`) → `jobs <dir> s01` → 그리기 → `cut` |
   | | 6×6 에서 두 번째 | 멈추고 사용자에게 알린다 — 견본이나 글씨 설명(`--style`)을 바꿔야 한다 |
   | | 됨이 아님 — 이 격자로 받아 둔 다른 장이 있다(첫 장만 다시 받는 중) | 같은 격자로 다시 받고, 두 번이면 멈추고 묻는다. 격자는 못 낮춘다(`grid --down` 이 거절한다 — 받은 장을 지키려고) |
   | 그 뒤의 장 | 일부 | 그대로 간다 — 못 쓰는 줄의 글자는 `redo` 가 다시 쓰기 장으로 보낸다 |
   | | 안 됨 — 처음 | `retry <dir> <장>` → `jobs <dir> <장>` → 그리기 → `cut <dir> <장>` |
   | | 안 됨 — 두 번째 | 멈추고 사용자에게 묻는다(한 번 더 / 그 장 글자를 다시 쓰기 장으로 / 그만). 격자는 낮추지 않는다 |

   **다시 받을 때는 늘 `retry <dir> <장>` → `jobs <dir> <장>`** 이다. `retry` 는 받은 그림을 `inbox/rejected/` 로 치우고 그 장의 칸·검수 그림·묶음을 지운다(`openai --retry` 와는 다른 것이다). 다시 받기는 **떨어졌다는 것과 한 장 값이 더 든다는 것을 사용자에게 한 줄로 알리고** 간다. `cut` 은 `review/<장>.png`(에이전트용 — 6×6 보다 큰 격자는 6×6 칸씩 쪽을 나눠 `review/<장>-p01.png` …)와 `review/index.html`(사람용)을 만든다. 빈 칸은 빨간 테두리, 장 검사가 못 쓴다고 한 칸은 주황 테두리로 보인다. 영문 장과 일본어 모드는 장 검사 없이 예전대로 자른다(격자를 못 찾으면 6등분).
6. **검수는 빼지 않는다.** 모델은 드문 글자에서 틀린다(6×6 실측 1,872칸 중 63칸: ㅠ·ㅛ 다리 하나, ㅁ 을 ㅇ 처럼, 받침 ㅅ→ㅆ, ㄻ·ㄶ→ㄼ, ㅞ·ㅙ 세로획 빠짐). 틀린 칸은 **작업 폴더 바로 아래의 `errors.json`**(`font.json` 옆)에 적는다: `{"s07": {"24": "?"}}` = 버림, `{"s07": {"24": "쬐"}}` = 실제로는 '쬐'를 씀. 칸 이름은 행·열(0부터): 10×10 까지는 한 자리씩 `"24"`, 11×11 부터는 두 자리씩 `"0213"`(3번째 줄 14번째 칸). 기준은 `references/review.md`.
   - 에이전트는 검수 그림을 한 쪽씩 보며 칸마다 파란 글자와 손글씨를 대조해 틀린 칸을 `errors.json` 에 **제안**으로 적고 `review <dir>` 를 돌린다(페이지는 만들 때의 `errors.json` 을 담는다 — 고친 뒤에는 꼭 다시 돌린다).
   - 사용자는 `review/index.html` 에서 칸을 눌러 확인 · 고친다. 페이지는 파일을 쓰지 못한다 — **페이지 아래에 생긴 JSON 을 사용자가 복사해 에이전트에게 붙여 주면 에이전트가 그 JSON 으로 `errors.json` 을 통째로 바꿔 저장한다**(사용자가 직접 저장해도 된다). 그 뒤 `review <dir>`.
   - **둥근 글씨의 ㅁ**: 둥근 글씨는 ㅁ 이 ㅇ 처럼 둥글게 나오기 쉽다(3단계 둥글펜 14×14 — 첫 장 196칸 가운데 셋, 다시 쓰기 장 두 장이 통째로 이 실수). ㅁ 이 든 글자는 `compare` 로 크게 보고, **위 · 아래 모서리가 보이는 상자일 때만 맞음**으로 친다 — 애매하면 틀림으로 두고 사용자에게 그림을 보여 주고 정한다.
   - 장을 통째로 버리려면(예: 사용자가 다시 쓰기 장을 받아들이지 않을 때) `errors.json` 에 `{"r01": "*"}` 처럼 장 이름에 `"*"` 를 준다 — 그 장의 칸은 하나도 쓰이지 않고 `redo` 가 그 글자를 다시 쓰기 장으로 보낸다(본문 · 부호 · 다시 쓰기 장 모두).
   - 마지막 본문 장의 남는 칸에 들어간 **목표 밖 글자**(14×14 · 500자면 본문 588칸이라 88자가 더 쓰인다)도 본다 — 맞으면 폰트에 들어가고, 틀려서 `"?"` 로 버리면 그냥 빠진다(`redo` 는 목표 글자와 부호만 다시 쓰기 장으로 보낸다).
7. `redo <dir> [--print] [--replace]` — 아직 없는 본문 글자(틀린 칸 · 못 쓰는 줄 · 안 된 장의 글자)만 모아 그 폰트의 격자로 다시 쓰기 장(흔한 실수 목록 + 자모 풀이, `--print` 면 활자 철자 참조 ref-3). 부호 장에서 빠진 글자(예: ★ 를 ☆ 로 그림)는 부호 장 형식의 다시 쓰기 장으로 따로 만든다. **다시 쓰기 장도 한 장 값씩 든다 — `redo` 가 장 수 × 장당 값을 새 견적으로 내고, 그 견적을 말하고 다시 승인(`approve --note`)받기 전에는 `check` · `spend` · `openai` 가 멈춘다.** 다시 쓰기 장의 형식 참조(ref-2)는 기본이 "검수에서 틀린 칸이 가장 적은 '됨' 본문 장(같으면 앞 장)"이고, `jobs <dir> <장> --format <장>` 으로 고를 수 있다(3단계에서 실수가 있던 첫 장을 형식 참조로 쓴 다시 쓰기 장 둘은 기준에 맞는 ㅁ 이 0, 실수 없는 둘째 장을 쓴 장은 108칸 가운데 11 — 한 번뿐인 비교다). 의심 칸은 `compare <dir> <장>:<칸> …` 로 크게 보고 활자 참조와 대조한다. 안 받은 다시 쓰기 장이 남아 있으면 멈춘다(같은 글자에 두 번 내지 않게) — 그 장을 버리고 새로 만들려면 `--replace`. 두 번 해도 안 되는 글자는 멈추고 사용자에게 알린다(대체 글꼴로 나오게 두는 것도 답이다).
8. `glyphs <dir>` → `python scripts/build_font.py <dir>` → `bold <dir> [--units 14]` → `python scripts/build_font.py <dir> --bold` → `preview <dir>`(설치 없이 `out/preview.html` 로 가로·세로 조판 보기). 결과 `out/<PS>-Regular.ttf`·`-Bold.ttf`(같은 가족 — Word 굵게 단추·CSS 700 이 굵은 파일을 고른다). 2,350자 조립은 한 굵기에 10분 넘게 걸릴 수 있다(백그라운드로).
9. 설치(사용자가 원할 때만): Windows `pwsh -File scripts/install-windows.ps1 <ttf> "<가족 이름> Regular (TrueType)"`(관리자 권한 필요 없음), macOS·Linux `sh scripts/install-unix.sh <ttf>...`.

`status <dir>` 로 언제든 받은 장·격자·장 검사 판정·없는 글자·쓴 돈·치운 그림을 본다.

## 2. 돈 규칙 (B·C — 어기지 않는다)
차례는 늘 같다: **견적을 말한다 → 승인받는다(`approve`) → 장마다 보내기 직전에 장부에 적는다.** 금액 한도는 두지 않는다 — 대신 돈이 더 드는 일(다시 받기 · 다시 쓰기 · 격자 낮추기)은 그때마다 한 장 값 · 새 견적을 다시 말한다.
1. **견적 먼저**: `estimate <dir>` 로 장 수 × 장당 값을 보여 준다(아무것도 올리거나 보내지 않는다). 본문 · 부호 장 값과 **따로** 두 가지를 같이 말한다: (가) 첫 장이 장 검사에 떨어지면 같은 격자로 한 번 더 = 한 장 값이 더 들고, 또 떨어져 격자를 낮추면 장 수가 위 표대로 늘어난다 (나) 다시 쓰기 장은 보통 한두 장이고 장마다 한 장 값이다. 장당 값이 `font.json` 의 값(기본 0.42)과 다르면 `estimate <dir> --price <그 값>` 을 한 번 돌린다 — `font.json` 에 적혀 그 뒤의 견적(`estimate` · `grid --down`)과 `openai` 의 장부 값이 그 값을 쓴다.
2. **사용자의 "예"**: 견적을 말하고 승인받으면 `approve <dir> --note "<사용자가 한 말>"` 로 적는다(`--note` 필수 — 사용자가 한 말을 그대로). 금액을 넣지 않는다. 승인 기록이 없으면 `check` · `spend` · `openai` 가 멈춘다(장당 0 으로 적는 Codex 내장 도구도). 계획 승인("해 봐")은 결제 승인이 아니다. (예전 `--cap` · `--sheets` 를 주면 무시한다고 한 줄 내고 승인만 적는다. 예전 폴더 `ledger.json` 에 남은 그 값도 읽지 않는다.)
3. **승인 뒤에만, 한 번에 한 장**: 한 장 그리기 전마다 `check <dir>` — 승인 기록이 있는가(격자가 바뀐 뒤라면 그 뒤의 승인이 있는가)만 본다. 멈추면 그리지 말고 사용자에게 묻는다. 여러 장을 한 호출로 보내는 도구(MCP batch, `n` > 1)는 쓰지 않는다. **첫 장이 통과하고 사용자와 글씨를 본 뒤에** 나머지를 그린다 — 그 전에는 스크립트가 다른 한국어 장을 막는다(`jobs` · `spend` · `openai`).
4. **기록은 보내기 전에** (장이 많아 서브에이전트에 나눠 맡길 때는 맡기는 쪽이 전부 먼저 적고, 서브에이전트는 장부를 건드리지 않는다 — `references/backend-agent.md`): C 는 한 장 보내기 **직전에** `spend <dir> --sheet <장> --usd <견적> --backend <codex|mcp|agent> --job <키>`(`--backend` 는 Codex 내장 도구면 `codex`, 이미지 MCP 서버면 `mcp`, 그 밖의 에이전트 도구면 `agent` — 안 주면 `agent`). **키는 `jobs/<장>/job.json` 의 `key`**(`<작업 폴더 이름>-<장>-g<격자>-<시도>`, 예 `my-font-s01-g14-1`)를 그대로 쓰고, 서버에 보내는 idempotency key 도 같은 값으로 한다 — 다시 받는 장과 낮춘 격자의 장은 키가 달라 장부에 따로 적히고 서버도 새 그림을 준다. 같은 `--job` 은 두 번 적히지 않으니 재시도 때 다시 불러도 된다. **`--usd` 에는 그 장의 서버 견적**을 적는다(보낼 payload 그대로 받은 값 — 장당 값은 프롬프트 길이 등으로 0.42 · 0.43 처럼 달라진다). `font.json` 의 장당 값은 사용자에게 말할 어림에만 쓴다. 금액은 0 이상만 받는다(실제 값이 달라도 음수로 "정정"하지 않는다). 응답 전에 끊긴 요청을 새 요청으로 다시 보내지 않는다(MCP 는 같은 idempotency key 로). **청구는 작업마다의 청구 값으로 맞춘다**(Sume 는 `jobs_wait` 결과의 `usage_summary.captured_usd`) — 거래 내역은 하루치를 묶어 보여 줘서 장부와 한 건씩 맞추는 데 쓰지 않는다. 장부와 다르면 장부를 고치지 말고 차이를 사용자에게 말한다.
5. **다시 받기 · 다시 쓰기 · 낮추기의 돈**: 같은 격자로 한 번 더(`retry`)는 **떨어진 것과 한 장 값이 더 든다는 것을 사용자에게 한 줄로 알리고** 간다. 다시 쓰기 장(`redo`)은 `redo` 가 낸 새 견적(장 수 × 장당 값)을 말하고 승인을 받아 `approve --note` 로 적는다 — 그 전에는 `check` · `spend` · `openai` 가 멈춘다. **격자를 낮추면(`grid --down`) 장 수가 바뀌므로 새 `approve` 가 있기 전까지 `check` · `spend` · `openai` 가 멈춘다** — `grid --down` 이 낸 새 견적을 말하고 다시 "예"를 받는다. 떨어진 그림에 든 돈은 돌아오지 않는다(`status`·`estimate` 가 치운 그림과 거기에 든 돈을 보여 준다). 가장 나쁜 경우 14×14 에서 6×6 까지 격자마다 두 장씩, 첫 장에만 그림 10장이 든다. 이 격자로 받아 둔 다른 장이 있으면 격자는 못 바꾼다(`grid --down` · `--set` · `--auto` 가 거절한다 — 다른 격자로 하려면 새 작업 폴더).
6. **키는 이름만**: API 키 값을 대화·파일·로그에 쓰지 않는다. 사용자가 자기 터미널에서 환경 변수로 넣는다.

## 3. 알아 둘 것
- **격자 규칙은 임시다.** 경계 0.09 · 14/12 · 줄 어긋남 15% · 못 쓰는 줄 20% · "한 번 더 뒤 낮춤"은 글씨체 다섯 개 · 장 18개(GPT Image 2.6, 2K)로 한 실험에서 나왔다. 그 실험에서 14×14 는 가는 글씨 세 개가 됐고(둥글펜은 두 번 받아 한 번은 되고 한 번은 안 됐다), 굵은 마커는 14×14 · 12×12 에서 떨어지고 10×10 에서 됐고, 붓펜은 12×12 · 14×14 가 됐다. 16×16 은 세 글씨체 모두 열이 하나 모자라게 나와 쓰지 않는다. "한 번 더"가 낮추기보다 나은지 가를 장은 아직 없다. 새 격자로 처음부터 끝까지 폰트 하나를 만들어 본 적도 아직 없다.
- **견본 재기**: 기울기(±12° 안)를 되돌리고 획 굵기를 화소보다 잘게 잰다. 받아 둔 견본을 돌리고(−6° ~ +10°) · 절반으로 줄이고 · 흐리게 · 그림자 · JPEG 로 바꾼 그림에서는 모두 같은 쪽(가는/굵은)으로 나왔다. **진짜 사진 견본으로는 아직 재 보지 않았다.** 견본은 긴 변 800px 이상으로 준다 — 획이 한두 화소뿐인 아주 작은 그림은 가는 쪽으로 틀어져 재진다.
- **가는 펜은 칸이 작을수록 획이 상대적으로 굵게 나온다** — 같은 견본으로 14×14 장의 획이 6×6 장의 1.3 ~ 1.6배였다. 그래서 한 폰트는 한 격자로 쓴다(본문 · 부호 · 다시 쓰기 장 모두). 영문 장만 6×6 이고, 조립 때 영문 획을 본문에 맞춰 키운다.
- 정확도는 GPT Image 2.6(2K)로 쟀다: 6×6 은 500자 432/432, 2,350자 1,809/1,872(첫 시도). 14×14 는 둥글펜 500자 한 벌에서 목표 500자 가운데 497(틀린 셋은 모두 첫 장의 ㅁ → ㅇ) — 한 벌뿐이다. 첫 장으로 먼저 확인하고 검수를 꼼꼼히 한다. 다른 모델도 첫 장으로 먼저 확인한다.
- 받는 그림은 정사각·긴 변 1,500px 이상 원본 PNG. 채팅 앱 미리보기 캡처는 흐려서 윤곽이 뭉개진다.
- 격자 정보가 없는 옛 작업 폴더(`font.json` 에 `grid` 가 없다)는 6×6 그대로다 — 만들던 폰트가 바뀌지 않는다. 6×6 한국어 장도 이제 장 검사를 거친다: 선 7개를 고르게 찾던 장의 칸 그림은 예전과 바이트까지 같고, 예전에 6등분으로 넘어가던 장(선 수가 틀리거나 칸 간격이 1.3배 넘게 고르지 않은 장)은 이제 "안 됨"이거나 찾은 선대로 잘린다. 첫 장 통과 전에 다른 장을 막는 것도 6×6 에 똑같이 든다.
- **영문**(`--latin` / `latin <dir>`): 한국어·일본어 폰트 모두 같은 3장(L1~L3, 본문 격자와 상관없이 6×6) — 대소문자 52 + ASCII 부호 32 + “ ” ‘ ’ – —. 칸마다 하늘색 안내선(대문자 높이·x-높이·기준선)을 긋고, 조립 때 기준선·x-높이에 맞추고 옆 여백·커닝을 넣는다. 폰트에 이미 있는 부호(한국어 , . ? ! 등)는 그대로 둔다. 첫 영문 장(L1)을 받아 확인한 뒤 나머지 2장. 같은 손글씨의 다른 폰트 폴더로 받은 영문 장은 `latin <dir> --from <그 폴더>` 로 옮겨 쓴다(다시 그리지 않는다). 검수는 대소문자(c/C, o/O, s/S …)와 기준선을 본다. 자세히 `references/latin.md`.
- **한국어(한글)** 는 기본 모드(`--script ko`, 생략 가능) — 격자·장 구성·자모 풀이·부호 장·장 검사·흔한 실수·조립 규칙은 `references/korean.md`.
- **일본어(가나·한자)** 는 `init --script ja` — 6×6 고정이다(`--grid` 는 못 쓴다 — 한자·가나는 작은 칸으로 재 본 적이 없다). 상용한자 2,136자 + 가나 + 부호를 69장·$30 으로 실제로 만들었다(첫 시도에 틀린 칸은 부호 ★ 하나). 세로쓰기(세로용 부호 모양 · vhea/vmtx · vert)도 조립 때 저절로 들어간다 — 그림을 더 그리지 않는다. 한자 목록은 `scripts/kanji-list.mjs`(빈도순, 자료 다운로드는 사용자에게 묻고). 한국어 손글씨에서 시작하면 `drafts --base` → `pick --whole` 로 일본어 견본부터. 자세히 `references/japanese.md`.
- 만든 폰트를 배포하려면 쓴 생성 서비스의 약관(출력물 상업 이용)을 사용자가 확인한다. 라이선스는 사용자가 정하고(무료 폰트는 보통 SIL OFL 1.1), `font.json` 에 `copyright` · `license`(짧은 설명) · `license_url` · `description` 을 적으면 조립 때 폰트 이름 표(0·13·14·10)에 들어간다.
