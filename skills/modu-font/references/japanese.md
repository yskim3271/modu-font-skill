# 일본어 모드 (`--script ja`)

가나·한자 손글씨 폰트를 한글과 같은 흐름(묶음 → 그리기 → cut → 검수 → 조립)으로 만든다.

## 실측 (2026-11-08, GPT Image 2.6 sunburst · 2K · max, Sume)
모두의 둥글펜 한국어 견본에서 시작해 **상용한자 2,136자(+대용 자형 3, 시험용 JIS 2수준 36) + 가나 171 + 부호 36 = 2,382자**를 만들었다.
- 장: 견본 1 + 가나 5 + 한자 61 + 부호 1 + ★ 다시 쓰기 1 = 69장, **$30.22**(장당 $0.42 — 활자 참조가 붙는 한자 장은 $0.44).
- 정확도(에이전트 눈 검수): 첫 시도에 틀린 칸은 부호 장의 ★ 하나(속 빈 ☆ 로 그림 → ☆ 로 쓰고 ★ 는 다시 쓰기, 프롬프트 고침). 한자·가나 칸은 틀린 것을 못 찾았다. 200px 칸 검수라 획 하나 차이는 놓쳤을 수 있다 — 일본어를 읽는 사람이 한 번 더 보는 게 좋다.
- 격자: 69장 모두 찾음, 빈 칸 0.
- 한글(2,350자 첫 시도 96.6%)보다 잘 나왔다. 한자 장에 늘 넣는 활자 참조(ref-3) 덕으로 본다 — 프롬프트 글자를 하나 잘못 보냈을 때도 모델은 ref-3 를 따라 맞는 글자를 썼다.

## 만들기
```
# 1) 한자 목록(빈도순) — kanji.json 은 사용자 허락을 받고 받는다(아래)
node scripts/kanji-list.mjs kanji.json chars-kanji.txt --set joyo        # 상용 2,136(+대용 자형 3) · kyoiku 면 교육 1,006
# 2) 작업 폴더
node scripts/hf.mjs init <dir> --script ja --chars chars-kanji.txt --family-en "My Hand JP" --family-ja "わたしの手書き" --style "<영어 글씨 설명>" [--sample 견본.png]
```
- 글자: 가나 171자(히라가나 ぁ~ん · 가타카나 ァ~ヶ · ー · 々, 장 `k01`~`k05`) + 한자(장 `s01`~) + 일본어 부호·숫자 36자(장 `sym`).
- 한자 목록 자료: [davidluzgouveia/kanji-data](https://github.com/davidluzgouveia/kanji-data) 의 `kanji.json`(MIT, 원자료 KANJIDIC — EDRDG CC BY-SA 4.0). grade 1~6 교육·8 상용, freq 신문 빈도. 받는 것은 다운로드라 **사용자에게 먼저 묻고**, 받은 파일은 새 빈 폴더에 둔다.
- 다운로드 없이: `--set jis1`(JIS 1수준 2,965자, 기본) · `jis12`(6,355자) 는 Node 내장 디코더로 만든다. **읽는 소리 순이라 빈도순이 아니다** — 일부만 만들 거면 빈도순 목록을 `--chars` 로.
- 2010 개정 표의 자형과 JIS 대용 자형(塡/填 · 剝/剥 · 頰/頬)은 둘 다 넣는다. 𠮟 는 BMP 밖이라 叱 만.
- `kanji-list.mjs --first 파일` 로 이미 받은 시험 장의 글자를 앞에 두면, 그 장(s01…)을 그대로 다시 쓴다(받은 장은 `jobs` 가 건너뛴다).
- `--count` 는 한자 수(가나·부호는 따로). `--kana no` 면 가나 장을 빼고 한자만(정확도 시험용 — 나중에 `font.json` 의 `kana` 를 true 로 바꾸고 `plan` 하면 가나 장이 앞에 붙고 받은 장 배치는 그대로).
- 목록은 작업 폴더 `chars-kanji.txt` 에 남는다(`plan` 이 다시 읽는다). 마지막 한자 장은 남은 글자를 되풀이해 36칸을 채운다(앞 칸만 쓴다).

## 견본 — 다른 글자 체계의 손글씨에서 시작할 때
한국어 손글씨(예: 모두의 둥글펜 견본)만 있으면, 같은 사람이 일본어로 쓴 견본을 먼저 한 장 그린다.
```
node scripts/hf.mjs drafts <dir> --base 한국어견본.png[,같은손의격자장.png]   # jobs/drafts — 한 장 값, 돈 규칙 그대로(spend --sheet drafts)
# 그림을 inbox/drafts.png 로 받은 뒤
node scripts/hf.mjs pick <dir> --whole [--style "<영어 글씨 설명>"]
```
견본 문장은 한국어 견본과 같은 내용(大変·全部·売·切·秋葉原·行·本当·走 가 들어 있다). 견본의 한자가 틀렸으면 그 견본은 쓰지 않는다 — 틀린 자형이 모든 장으로 퍼진다. 격자 장을 함께 참조로 주면 펜 굵기가 더 잘 옮는다.

## 권하는 순서
1. 견본 1장 → 사용자와 확인.
2. 시험 2~4장(흔한 한자 1, 획 많은 한자 1, 가나 1, 부호 1)을 `--kana no` 시험 폴더에서 → 검수로 정확도 확인.
3. 본 생성: 시험 폴더를 복사해 목록만 바꾸고(`--first`) `plan` → `jobs` → 견적·승인 → 나머지 장. 장이 많으면 `backend-agent.md` 의 "여러 장을 나눠 그리기".
4. 검수 → `redo`(가나·한자는 본문 다시 쓰기 장, 빠진 부호는 부호 다시 쓰기 장) → `glyphs` → 조립. 2,400자 조립은 한 굵기에 10분쯤.

## 한글과 다른 점
- 한자가 든 장은 **늘 활자 구조 참조(ref-3)** 를 넣는다. 일본어 글꼴(Yu Gothic → Meiryo → MS Gothic → Hiragino → Noto Sans CJK JP)로 그린다 — 한중일 통합 한자라 한국어 글꼴로 그리면 자형이 다르다. 그 글꼴이 없는 기계(한글 글꼴만 있는 Linux 등)에서는 ref-3 을 먼저 열어 보고 두부 상자면 멈춘다.
- 프롬프트의 한자 자형 문장은 "ref-3 에 보인 자형 그대로" — JIS 2수준에는 일부러 옛 자형인 글자(冩 獎 穩 등)가 있어서 "번체 금지" 라고 쓰면 부딪힌다.
- 자모 풀이 같은 철자 목록은 없다(ref-3 가 그 일을 한다).
- 조립: 가나·한자·전각 부호는 전각(1em) 고정 폭에 가운데. 크기 기준은 한자 잉크 높이(한자가 20자 미만이면 가나까지). 일본어 이름(name ID 1·4, 언어 0x411), OS/2 코드 페이지 JIS(17). 세로쓰기 정보도 함께 넣는다(아래).
- **아직 없는 것**: 가로쓰기 부호 자리(조립이 전각 부호를 칸 가운데로 모아 、。「」 앞뒤가 조금 뜬다). 영문과 반각 ! ? ( ) 등은 `latin` 으로 더한다(`references/latin.md`).

## 세로쓰기
일본 만화 말풍선처럼 위→아래로 쓸 때를 위해 `build_font.py` 가 일본어 폰트에 세로쓰기 정보를 넣는다. **그림을 새로 그리지 않는다** — 세로용 모양은 가로 글자의 윤곽을 돌리거나 옮겨 만든다.

| 글자 | 세로용 모양(`이름.vert`) |
|---|---|
| 、 。 ， ． | 칸 오른쪽 위로 옮김 |
| 「 『 （ 【 〈 《 〔 | 시계 90° 돌려 칸 아래쪽 반·오른쪽 — 다음 글자에 붙음 |
| 」 』 ） 】 〉 》 〕 | 시계 90° 돌려 칸 위쪽 반·왼쪽 — 앞 글자에 붙음 |
| ー 〜 ～ … ‥ ： － ＝ | 시계 90° 돌려 칸 가운데 |
| 작은 가나 ぁ…ゎ ァ…ヶ | 조금 오른쪽 위로 옮김 |

- 표: `vhea`(세로 ascent 500 / descent −500)·`vmtx`(모든 글자 높이 1em, 원점은 글자 상자 위), GSUB `vert`·`vrt2`(위 글자 → `.vert`). 가나·한자·！？♡ 는 그대로 선다.
- 확인: `node scripts/hf.mjs preview <dir>` → `out/preview.html` 을 브라우저로 연다(설치 없음). 세로 줄은 `writing-mode: vertical-rl` 이라 브라우저가 `vert` 로 세로용 모양을 고른다. Word·Illustrator 같은 앱은 설치 후 세로 쓰기로 본다.
- 실측(2026-11-08, 모두의 둥글펜 JP): 가나·한자는 세로로 그대로 자연스러웠고, 부호만 위 표대로 바꾸니 Edge 세로 조판에서 자연스럽게 읽혔다. 세로용 모양이 없던 때는 ー 가 가로줄로, 、。 가 칸 아래 가운데로 나와 어색했다.
- 손으로 쓴 모양을 그대로 돌리므로 〜 · ： 처럼 방향이 있는 부호는 원래 손글씨 기울기가 돌아간 채 남는다. 마음에 안 들면 세로용을 따로 그리는 장을 더할 수 있다(지금은 없음).

## 검수 (`references/review.md` 에 더해)
- 틀림: 획이 빠지거나 더해짐, 부수가 비슷한 다른 것으로 바뀜, 비슷한 다른 한자(未/末, 土/士, 己/已/巳, 人/入, 大/犬/太, 衤/礻), 중국 간체·번체 자형, 탁점·반탁점 빠짐, 작은 가나를 크게(또는 반대로), 있지 않은 글자를 지어냄, ★ 를 ☆ 로.
- 의심 칸은 `node scripts/hf.mjs compare <dir> s12:01 s14:34 …` 로 손글씨(크게)와 ref-3 활자를 위아래로 놓고 부수 단위로 맞춰 본다(`review/compare.png`).
- 손글씨에서 구별이 거의 안 되는 쌍이 있다(예: 頰/頬). 둘 다 그 글자로 읽히면 버리지 않는다.
- 정확도를 잴 때는 장마다 맞은 칸 / 36 과 틀린 칸의 종류(획 빠짐·부수 바뀜·지어냄)를 적는다.
