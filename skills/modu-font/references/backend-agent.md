# C. 에이전트가 자기 도구로 그리기

지금 에이전트에 이미지 생성 도구가 있을 때만, 그리고 **사용자가 이 방법을 고른 뒤에만** 쓴다. 묶음(`jobs/<장>/`)의 참조 그림과 `prompt.txt` 를 에이전트가 도구에 넣고 결과를 받는다.

## 처음 한 번 (차례를 바꾸지 않는다)
1. `estimate <dir>` — 아무것도 올리거나 보내지 않는다. 금액(Codex 는 장 수)을 사용자에게 말할 때 본문 · 부호 장 값과 **따로** 말한다: 첫 장이 장 검사에 떨어지면 같은 격자로 한 번 더 = 한 장 값, 다시 쓰기 장은 보통 한두 장(장마다 한 장 값). 금액 한도는 없다 — 그 몫이 실제로 필요해지면 그때 한 장 값을 다시 말한다.
2. 견본을 외부 서버에 올리는 방법(MCP 업로드)이면 **올리기 전에** 그것도 같이 말한다 — "견본(사용자의 글씨 그림)이 서버의 공개 주소로 올라간다". 금액과 업로드 둘 다 "예"를 받는다.
3. `approve <dir> --note "<사용자가 한 말>"`(금액은 넣지 않는다 — Codex 도 같다). 승인 기록이 없으면 `check` · `spend` 가 멈춘다.
4. 그 뒤에 업로드 → 서버 견적. **견적은 보낼 payload 그대로 받는다**(줄이거나 바꾼 payload 로 받지 않는다 — 장당 값은 프롬프트 길이 등으로 0.42 · 0.43 처럼 달라진다). Sume 는 키가 필요 없는 `estimate_image_cost`(같은 payload), `dry_run` 을 쓰는 서비스라면 그 키는 `<job.json 의 key>-dryrun`. 서버 견적이 승인받은 장당 값보다 크면 그리지 말고 멈춰 사용자에게 다시 묻는다(그 값으로 승인받으면 `estimate <dir> --price <서버 값>` 을 한 번 돌린다 — `font.json` 에 적혀 그 뒤의 견적이 그 값을 쓴다).

## 공통 순서 (장마다 — 한 호출에 한 장)
1. `node scripts/hf.mjs check <dir>` — 승인 기록이 있는가만 본다. 종료 코드가 0 이 아니면(=멈춤) 그리지 말고 사용자에게 묻는다.
2. `node scripts/hf.mjs spend <dir> --sheet <장> --usd <견적> --backend <codex|mcp|agent> --job <키>` — **보내기 직전에** 적는다(`--backend` 는 Codex 내장 도구면 `codex`, 이미지 MCP 서버면 `mcp`, 그 밖의 에이전트 도구면 `agent` — 안 주면 `agent`). **키는 `jobs/<장>/job.json` 의 `key`**(`<작업 폴더 이름>-<장>-g<격자>-<시도>`, 예 `my-font-s01-g14-1`)를 그대로 쓴다 — 도구가 정해 준다. 같은 `--job` 은 한 번만 적히므로 재시도 때 다시 불러도 된다. 금액은 0 이상만(실제 값이 견적과 달라도 음수로 정정하지 않는다). 한국어 모드에서 첫 장이 통과하기 전에 다른 한국어 장(본문 · 부호 · 다시 쓰기)을 주면 `spend` 가 적지 않고 멈춘다 — 그 장은 그리지 않는다.
3. `jobs/<장>/job.json` 의 `refs` 를 그 차례대로 참조 그림으로, `prompt.txt` 를 **바꾸지 않고** 프롬프트로 넣는다. 크기는 정사각, 가장 큰 것. **여러 장을 한 호출로 보내지 않는다**(MCP 의 batch 도구, `n` > 1 금지 — 서버 안내가 batch 를 권해도). 
   - 프롬프트는 `prompt.txt` 를 읽어 그대로 넣는다. **기억으로 다시 쓰지 않는다** — 한자 하나가 비슷한 글자로 바뀐다(柝 를 枝 로 보낸 적이 있다; 그때는 ref-3 활자 덕에 모델이 柝 를 썼다). 도구 호출 JSON 에서 글자가 `\uXXXX` 로 나가는 것 자체는 손실이 없다.
   - **보내기 전**: `node scripts/hf.mjs verify-prompt <dir> <장>` 이 종료 코드 0 이어야 보낸다 — `prompt.txt` 의 `Row` 줄이 `sheets.json` 과 칸마다 같은가, 활자(`kind: print`)면 손글씨 낱말 0줄인가, 자모 풀이에 오타가 없는가, `job.json` 의 `ref_sha256` 이 지금 참조 그림과 같은가(올릴 그림이 바뀌지 않았나)를 본다.
   - **보낸 뒤**: 서버가 돌려준 입력 프롬프트(작업 조회 결과 JSON 을 그대로 저장해도 된다 — `Row 1:` 이 든 글을 찾아 쓴다)를 파일로 두고 `verify-prompt <dir> <장> --echo <그 파일>` 로 칸 하나씩 대조한다(눈 대조는 비슷한 한자 · 획 하나 차이를 놓친다). 다르면 (행, 열, 기대, 실제)가 나오고 종료 코드 1 — 다시 보내지 말고 그 칸을 검수 때 표시한다. 서버가 끝 줄바꿈을 지우는 것은 괜찮다.
4. 결과 원본 PNG 를 `inbox/<장>.png` 로 저장한다(다른 곳에 저장됐으면 복사).
5. **받은 장은 장마다 바로 `cut <dir> <장>`** 한다(떨어진 장을 일찍 안다). `cut` 이 `→ 다음:` 으로 말하는 대로 한다(아래 "장 검사에 떨어졌을 때"). 종료 코드가 2(`경고:`)면 그 장은 통과가 아니다 — 다음 장으로 가지 않는다.
6. 처음 한 장(s01)은 `cut` 후 사용자와 같이 본 다음 나머지를 그린다. **첫 장 통과**(장 검사 "됨" — 그 그림이 `style/format.png` 가 된다) 전에는 `jobs` 가 s01 묶음만 만들고, `jobs --all` 로 미리 만든 묶음이 있어도 첫 장만 그린다.
- AI 시안(`jobs/drafts`)도 한 장 값이고 같은 순서를 따른다(`--sheet drafts`).

## 장 검사에 떨어졌을 때 (한국어 장)
`cut` 이 `경고:`(종료 코드 2)와 함께 `→ 다음:` 을 말한다. 같은 내용이 `cells/<장>/cells.json` 의 `next.action` 에 있다(`go` · `redo` 만 종료 코드 0): `go` 간다 · `retry` 같은 격자로 다시 · `down` 격자를 낮춘다 · `redo` 그대로 가고 못 쓰는 줄은 다시 쓰기로 · `ask` 멈추고 사용자에게 묻는다 · `stop` 더 내려갈 격자가 없다.
- **다시 받기**(`retry`): 사용자에게 한 줄로 알린다(떨어진 것과 한 장 값이 더 든다는 것). `node scripts/hf.mjs retry <dir> <장>` → `jobs <dir> <장>` → 새 `job.json` 의 `key`(시도 번호가 올라간다 — `…-g14-2`)로 위 공통 순서 1~4 를 다시. **예전 키를 다시 쓰지 않는다** — 서버가 떨어진 그림을 그대로 돌려준다. 참조 그림(ref-1 · ref-2)은 그대로라 서버에 올려 둔 주소를 다시 써도 된다.
- **격자 낮추기**(`down`): `node scripts/hf.mjs grid <dir> --down` → 화면에 나온 새 장 수 · 견적을 사용자에게 말하고 "예"를 받아 `approve <dir> --note "<사용자가 한 말>"` → `jobs <dir> s01` → 공통 순서. `down` 은 그 격자에서 장 검사에 떨어진 첫 장 그림이 두 장일 때만 나온다. 이 격자로 받아 둔 다른 장이 있으면 `grid --down` 은 거절한다(한 폰트 한 격자). **새 승인 전에는 `check` · `spend` 가 멈춘다.** 빈 격자(ref-2)가 새 격자로 바뀌므로 서버에 올려 둔 예전 빈 격자 주소를 쓰지 말고 새 `ref-2.png` 를 다시 올린다. 키에 격자가 들어 있어(`…-g12-1`) 예전 s01 과 겹치지 않는다.
- 떨어진 그림은 `inbox/rejected/` 에 남는다(지우지 않는다 — 장부와 맞춰 볼 수 있게). 떨어진 그림을 다른 장의 참조로 쓰지 않는다.
- `ask` · `stop` 이면 더 그리지 않고 사용자에게 그대로 알린다.

## 6×6 구제 장(pNN — `redo --rescue`) 보내기
- 차례는 위 공통 순서와 같다(새 견적 → 승인 → `approve` → 장마다 `check` → `verify-prompt <dir> pNN` → `spend --job <job.json 의 key — …-pNN-g6-<시도>>` → 그리기 → `verify-prompt <dir> pNN --echo <파일>` → `inbox/pNN.png` → `cut <dir> pNN`).
- 참조 그림은 셋이다: ref-1 견본, ref-2 스케일-매칭 6×6(`style/ref-2-scale6.png` — 구제 장마다 같은 파일이라 한 번 올린 주소를 `style/uploaded.json` 의 sha256 으로 다시 쓴다), ref-3 활자 구조 참조(장마다 다르다).
- `cut <dir> pNN` 이 앵커 보정을 한다. **게이트 리젝트(종료 코드 2 · `next.action: retry`)면 그 그림은 쓰지 않는다** — 한 장 값이 더 든다는 것을 알리고 `retry <dir> pNN` → `jobs <dir> pNN` → 새 키로. 통과면 `review/pNN-anchor-compare.png` · `review/pNN-context-mix.png` 를 사용자와 같이 보고, 타깃 칸은 `review/pNN.png` 로 검수한다(애매한 칸은 `compare … --band`).

## 여러 장을 나눠 그리기 (서브에이전트)
장이 많으면(예: 일본어 상용한자 61장) 서브에이전트 여럿에 10장 안팎씩 나눠 맡긴다. 실측: 6개 × 10장, 61장이 약 11분, 실패·재제출 0.
1. **돈은 맡기는 쪽이 먼저 다 적는다**: 견적 → 사용자 "예" → `approve` → 맡길 장마다 `check` → `spend --job <그 장 job.json 의 key>` 를 미리 끝낸다. 서브에이전트는 `approve`·`check`·`spend` 를 부르지 않는다(장부를 여럿이 동시에 쓰면 기록이 섞인다).
2. 각 서브에이전트에게 줄 것: 맡은 장 목록, 고정 참조 주소(견본·형식 장 — 이미 서버에 있으면 그대로), 한자 장의 ref-3 업로드 방법, 모델·설정, `idempotency_key` 규칙(`spend` 의 `--job` 과 같게), "한 호출에 한 장, batch·`n` 금지, 새 키로 다시 보내지 않기, 실패하면 기록만", `prompt.txt` 를 그대로 넣고 돌려준 프롬프트를 파일로 저장해 `verify-prompt <dir> <장> --echo <파일>` 로 대조하기, 받은 그림은 `inbox/<장>.png`, 결과는 `progress/<장>.json`(`sheet`·`job_id`·`artifact_url`·`rows_match`·`status`).
3. 서브에이전트는 `cut` · `retry` · `grid` 를 돌리지 않는다. 받은 장부터 맡기는 쪽이 장마다 바로 `cut <dir> <장>` → 검수. 장 검사에 떨어진 장(`경고:`)은 맡기는 쪽이 `retry` → `jobs` → `check` → `spend`(새 키) 뒤에 다시 맡긴다.
4. 다 끝나면 `progress/*.json` 의 `status` 와 서버 청구액을 장부와 맞춰 본다.

## Codex 내장 이미지 도구 (image_gen)
- ChatGPT 로그인으로 돌아 API 키가 필요 없다. 사용량은 사용자 Codex 계정에서 깎인다 — 장당 값은 0 으로 적되 장 수를 미리 말하고 승인받아 `approve <dir> --note …` 로 적는다. 장마다 `check` → `spend --usd 0`.
- 참조 그림은 `view_image` 로 대화에 올린 뒤 생성한다. 생성된 파일은 `$CODEX_HOME/generated_images/...` 에 있으니 `inbox/<장>.png` 로 복사한다.
- 내장 도구가 실패하면 B(OpenAI 키)로 몰래 바꾸지 않는다. 사용자에게 B 가 있고 키가 필요하다고만 말한다.

## 이미지 MCP 서버 (예: Sume)
- 참조 그림은 공개 https 주소가 필요하다: 서버의 업로드 도구(Sume: `media_upload` → 안내대로 PUT → `media_confirm`)로 `ref-*.png` 를 올리고 받은 주소를 `input_references` 로.
- 업로드는 위 "처음 한 번"의 승인 뒤에 한다. 그다음 장마다 **보낼 payload 그대로** `estimate_image_cost`(키 없음)로 견적 → 승인받은 장당 값보다 크면 멈추고 다시 묻는다 → `check` → `spend --usd <그 서버 견적>`. 사용자 승인 없이 실제로 보내지 않는다. 지정한 모델이 서버에 없으면 다른 모델(Auto 등)로 바꾸지 말고 멈춰 사용자에게 묻는다(값·정확도가 달라진다).
- 실제 호출: `idempotency_key` 는 `jobs/<장>/job.json` 의 `key`(`<작업 폴더 이름>-<장>-g<격자>-<시도>` — `spend` 의 `--job` 과 같은 값), `max_spend_usd` 는 서버 견적과 같게(조금 높게 하더라도 사용자에게 말한 장당 값을 넘지 않게). 네트워크가 끊겨도 **새 키로 다시 보내지 않는다**(같은 키로 다시 보내면 한 번만 청구된다).
- 끝나면 결과 주소의 원본을 받아(`curl -o inbox/<장>.png <주소>`) 서버가 알려 준 sha256 과 같은지 보고 저장한다. 장부는 보내기 전에 적은 서버 견적으로 둔다. **청구 맞추기는 작업마다의 `usage_summary.captured_usd`(`jobs_wait` 결과)로** 한다 — 거래 내역(`transactions`)은 작업 공간의 하루치를 묶어 보여 주고 다른 사용이 섞여 한 건씩 맞출 수 없다. 장부와 다르면 장부를 고치지 말고 그 차이를 사용자에게 말한다.
- 우리가 쓴 값: Sume `openai/gpt-image-2.6-sunburst`, `resolution: "2K"`, `quality: "max"`, `aspect_ratio: "1:1"`, `background: "opaque"` — 장당 $0.42(참조 2장) · $0.44(참조 3장).
- **이미 올린 참조 그림은 다시 올리지 않는다** — 처음 올린 참조(견본 · 빈 격자 · 형식 참조)의 주소를 작업 폴더의 `style/uploaded.json` 에 그 파일의 sha256 과 함께 적고(`{"<sha256>": {"url": "https://…", "file": "jobs/s01/ref-2.png", "at": "…"}}` — 에이전트가 쓴다), 다음 장부터는 `jobs/<장>/job.json` 의 `ref_sha256` 이 같으면 그 주소를 다시 쓴다. 받은 장(서버 결과 주소)은 `inbox/<장>.png` 의 sha256 으로 같은 파일 — 형식 참조가 받은 장이면 결과 주소를 그대로 쓴다. 견본은 `init` 이 PNG 로 다시 저장해 `ref-1.png` 의 sha256 이 원래 파일과 다르다 — `font.json` 의 `sample_source_sha256`(사용자가 준 원래 파일)으로 서버에 이미 있는 견본인지 맞춰 본다. 스킬은 업로드하지 않는다(기록 자리와 규칙만).

## 하지 않는 것
- 사용자가 고르지 않은 유료 도구로 그리기, 승인 없이 그리기, 키 값 다루기, `prompt.txt` 를 "더 낫게" 고쳐 보내기(정확도는 이 문구로 쟀다 — 고치려면 사용자와 먼저 한 장으로 비교).
