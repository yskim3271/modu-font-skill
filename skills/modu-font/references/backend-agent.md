# C. 에이전트가 자기 도구로 그리기

지금 에이전트에 이미지 생성 도구가 있을 때만, 그리고 **사용자가 이 방법을 고른 뒤에만** 쓴다. 묶음(`jobs/<장>/`)의 참조 그림과 `prompt.txt` 를 에이전트가 도구에 넣고 결과를 받는다.

## 처음 한 번
`estimate` → 금액(Codex 는 장 수)을 사용자에게 말하고 "예"를 받는다 → `approve <dir> --cap <USD> --note "<사용자가 한 말>"`(Codex: `--sheets <장 수>`). 승인 기록이 없으면 `check` 가 멈춘다.
견본 그림을 외부 서버에 올리는 방법(MCP 업로드)이면 그것도 함께 말한다 — 사용자 손글씨가 서버의 공개 주소로 올라간다.

## 공통 순서 (장마다 — 한 호출에 한 장)
1. `node scripts/hf.mjs check <dir> --usd <장당 값>` — 종료 코드가 0 이 아니면(=멈춤) 그리지 말고 사용자에게 묻는다.
2. `node scripts/hf.mjs spend <dir> --sheet <장> --usd <견적> --backend <codex|mcp> --job <idempotency key>` — **보내기 직전에** 적는다. 같은 `--job` 은 한 번만 적히므로 재시도 때 다시 불러도 된다. 금액은 0 이상만(실제 값이 견적과 달라도 음수로 정정하지 않는다).
3. `jobs/<장>/job.json` 의 `refs` 를 그 차례대로 참조 그림으로, `prompt.txt` 를 **바꾸지 않고** 프롬프트로 넣는다. 크기는 정사각, 가장 큰 것. **여러 장을 한 호출로 보내지 않는다**(MCP 의 batch 도구, `n` > 1 금지 — 서버 안내가 batch 를 권해도). 
   - 프롬프트는 `prompt.txt` 를 읽어 그대로 넣는다. **기억으로 다시 쓰지 않는다** — 한자 하나가 비슷한 글자로 바뀐다(柝 를 枝 로 보낸 적이 있다; 그때는 ref-3 활자 덕에 모델이 柝 를 썼다). 도구 호출 JSON 에서 글자가 `\uXXXX` 로 나가는 것 자체는 손실이 없다.
   - 보낸 뒤 서버가 돌려준 입력 프롬프트의 `Row` 줄을 `prompt.txt` 와 **스크립트로** 대조한다(눈 대조는 비슷한 한자를 놓친다). 다르면 다시 보내지 말고 그 칸을 검수 때 표시한다. 서버가 끝 줄바꿈을 지우는 것은 괜찮다.
4. 결과 원본 PNG 를 `inbox/<장>.png` 로 저장한다(다른 곳에 저장됐으면 복사).
5. 처음 한 장은 `cut` 후 사용자와 같이 본 다음 나머지를 그린다. 첫 장 전에는 `jobs` 가 s01 묶음만 만든다.
- AI 시안(`jobs/drafts`)도 한 장 값이고 같은 순서를 따른다(`--sheet drafts`).

## 여러 장을 나눠 그리기 (서브에이전트)
장이 많으면(예: 일본어 상용한자 61장) 서브에이전트 여럿에 10장 안팎씩 나눠 맡긴다. 실측: 6개 × 10장, 61장이 약 11분, 실패·재제출 0.
1. **돈은 맡기는 쪽이 먼저 다 적는다**: 견적 → 사용자 "예" → `approve` → 맡길 장마다 `check` → `spend --job <작업 폴더>-<장>-1` 를 미리 끝낸다. 서브에이전트는 `approve`·`check`·`spend` 를 부르지 않는다(장부를 여럿이 동시에 쓰면 기록이 섞인다).
2. 각 서브에이전트에게 줄 것: 맡은 장 목록, 고정 참조 주소(견본·형식 장 — 이미 서버에 있으면 그대로), 한자 장의 ref-3 업로드 방법, 모델·설정, `idempotency_key` 규칙(`spend` 의 `--job` 과 같게), "한 호출에 한 장, batch·`n` 금지, 새 키로 다시 보내지 않기, 실패하면 기록만", `prompt.txt` 를 그대로 넣고 돌려준 `Row` 줄을 스크립트로 대조하기, 받은 그림은 `inbox/<장>.png`, 결과는 `progress/<장>.json`(`sheet`·`job_id`·`artifact_url`·`rows_match`·`status`).
3. 서브에이전트는 `cut` 을 돌리지 않는다. 끝난 묶음부터 맡기는 쪽이 `cut <dir> <장…>` → 검수.
4. 다 끝나면 `progress/*.json` 의 `status` 와 서버 청구액을 장부와 맞춰 본다.

## Codex 내장 이미지 도구 (image_gen)
- ChatGPT 로그인으로 돌아 API 키가 필요 없다. 사용량은 사용자 Codex 계정에서 깎인다 — 장당 값은 0 으로 적되 장 수를 미리 말하고 승인받아 `approve <dir> --sheets <장 수> --note …` 로 적는다. 장마다 `check --usd 0` → `spend --usd 0` — 승인한 장 수를 넘으면 `check` 가 멈춘다.
- 참조 그림은 `view_image` 로 대화에 올린 뒤 생성한다. 생성된 파일은 `$CODEX_HOME/generated_images/...` 에 있으니 `inbox/<장>.png` 로 복사한다.
- 내장 도구가 실패하면 B(OpenAI 키)로 몰래 바꾸지 않는다. 사용자에게 B 가 있고 키가 필요하다고만 말한다.

## 이미지 MCP 서버 (예: Sume)
- 참조 그림은 공개 https 주소가 필요하다: 서버의 업로드 도구(Sume: `media_upload` → 안내대로 PUT → `media_confirm`)로 `ref-*.png` 를 올리고 받은 주소를 `input_references` 로.
- 먼저 같은 인자에 `dry_run: true` 로 견적 → 그 값으로 `check`. 사용자 승인 없이 실제로 보내지 않는다. 지정한 모델이 서버에 없으면 다른 모델(Auto 등)로 바꾸지 말고 멈춰 사용자에게 묻는다(값·정확도가 달라진다).
- 실제 호출: `idempotency_key` 는 `<작업 폴더 이름>-<장>-<시도 번호>` 처럼 장마다 고정, `max_spend_usd` 는 견적보다 조금 높게 하되 `check` 가 알려 준 남은 돈을 넘지 않게. 네트워크가 끊겨도 **새 키로 다시 보내지 않는다**(같은 키로 다시 보내면 한 번만 청구된다).
- 끝나면 결과 주소의 원본을 받아(`curl -o inbox/<장>.png <주소>`) 저장한다. 장부는 보내기 전에 적은 견적으로 둔다(실제 값은 서버 사용 내역이 정답).
- 우리가 쓴 값: Sume `openai/gpt-image-2.6-sunburst`, `resolution: "2K"`, `quality: "max"`, `aspect_ratio: "1:1"`, `background: "opaque"` — 장당 $0.42(참조 2장) · $0.44(참조 3장).
- 서버에 이미 있는 그림(이전 결과의 artifact 주소)은 다시 올리지 않고 참조로 쓴다 — 견본(`drafts`)과 첫 장은 한 번 받으면 모든 장의 ref-1·ref-2 주소가 된다.

## 하지 않는 것
- 사용자가 고르지 않은 유료 도구로 그리기, 상한을 넘겨 그리기, 키 값 다루기, `prompt.txt` 를 "더 낫게" 고쳐 보내기(정확도는 이 문구로 쟀다 — 고치려면 사용자와 먼저 한 장으로 비교).
